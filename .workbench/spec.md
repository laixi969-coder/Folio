# 简序 Folio · 产品需求文档

把文字与图片，排成舒服的一篇。

## 1. 定位与范围

为作者本人设计的响应式网页工具。内容主要来自 AI 文字和 Word，文章以观点与故事类长文为主。视觉志、智族 Lab 作为审美方向，整体取克制的颜色、清晰层级与舒服留白，不复制特定刊物模板。

手机端、电脑端、预览是第一版不可削减的能力。手机端能完整制作文章，不能只有只读预览。界面设计和基础编辑需要实际可用，不交付只有装饰按钮的静态稿。

不做 native App。电脑浏览器与手机浏览器访问同一服务。个人本地版数据落在本机目录；局域网访问要求电脑开机、服务运行、两端在同一网络。公网同步属于后续部署，不能把 localStorage 或手动备份冒充自动跨设备同步。

## 2. 一次完整使用过程

1. 打开文章库，粘贴 AI 文本或选择 .docx 文档；旧式 .doc 明确提示另存为 .docx。
2. 解析 Markdown、标题、列表、引用和 Word 内嵌图片，预览导入结果后建立草稿。
3. 导入后自动套用「留白 · 长文」并直接打开阅读预览，不要求先调整参数。预览提供「满意，去导出」及「继续微调」。保留原文与图片顺序，不自动润色、改标题、删句或拆段。
4. 点击某段指定插入位置。上传照片并组成图片组，选择单图、并排、网格、纵排、无缝或横滑。
5. 查看配图建议：提供位置、理由、画面及形式；用户决定上传或忽略，不自动插图。
6. 电脑调整整体结构，手机通读。草稿自动保存，两端共享服务端版本；冲突时保留本地副本，不静默覆盖。
7. 打开无编辑控件的预览，切换阅读宽度，操作滑动图组。返回保持位置。
8. 选择基础兼容导出，复制或下载正文；封面、发布标题独立处理。在公众号后台检查图片、间距并做微信真机预览，再由用户发布。

## 3. 页面与操作

### 3.1 文章库

首屏显示真实草稿/待通读数量、继续最近文章、新建和导入入口。空库提供具体行动，示例由用户主动打开且标记为示例。搜索文章标题、复制草稿、删除前确认。不要伪造已发布状态或阅读数据。

### 3.2 电脑编辑器

顶部：返回文章库、文章名称、保存状态、撤销/重做、预览、导出。
左侧：大纲/图片/配图建议切换。无标题的故事文章用段落开头定位，不改正文。
中间：发布标题与封面区可折叠；正文是手机阅读宽度白色画布；选中段落后直接编辑，支持新段落、类型转换和移动。
右侧：无图片选中时显示一键排版入口，手动参数默认折叠；选中图片组时显示布局、间距、裁切、排序、说明。
窄电脑或平板用可收起面板，不能挤压正文为细条。桌面预览支持编辑/预览并排及全屏通读。

### 3.3 手机编辑器

顶部：返回、保存状态、预览、导出。主区单栏可编辑正文，底部工具条提供插入、图片、样式、大纲。面板以底部抽屉出现，完成后收起；操作不依赖 hover 或拖拽。图片和段落移动必须有按钮替代。所有触摸目标至少 44px，适配安全区与软键盘，底栏不遮最后一段。

### 3.4 预览

复用同一文档和同一正文渲染规则，不能另写一份样例。电脑可切 320/375/414px 与宽屏，手机自动适配屏幕。隐藏辅助边框、配图建议、空占位、编辑工具。图片横滑可以真实操作。预览与微信实机结果有区别，导出前提示最终校验，不写「100%还原」。

## 5. 文字与文档输入

- 粘贴纯文本、Markdown、富文本；清理危险 HTML，允许必要的加粗、链接、列表、标题等。
- 导入 .docx 的文字、层级、图片与顺序；不执行文档中的代码或外部资源。
- 复杂 Word 表格、批注、脚注、文本框、分页式布局有降级说明，不声称还原印刷版。
- 上传类型不支持、文档损坏、大小超限显示具体错误，原草稿保持不动。
- 支持中文输入法合成，正文输入不因重渲染跳光标。
- 格式操作作用于选中段落，支持撤销/重做；删除有恢复路径。

## 6. 图片组

| 布局 | 行为 | 导出策略 |
|---|---|---|
| 单图/纵排 | 原比例顺序排列 | 基础内联样式 |
| 双列/网格 | 选择原比例或统一裁切，单张主体位置可调 | 表格式兼容布局，需微信实测 |
| 无缝 | 图间距为0，连续展示 | 去除图间空隙，需微信实测 |
| 横向滑动 | 手动滑动、下一张露出或文字提示、保留顺序 | 工具和HTML中可互动；公众号兼容导出显式转纵排 |
| 自动轮播/点击展开 | 进阶互动 | 后续专项验证，不伪装已支持 |

每组支持增删图片、换图、排序、拆分、整体图注、逐图图注、替代文字。改变布局不丢失内容。裁切非破坏性保留原文件，图片有源文件与显示位置。封面和正文首图分别保存；封面可选宽图/方图预览裁切，独立下载，不混入正文。

建议：重要证据与影响理解的图片直接显示；辅助照片可用横滑。不默认自动播放，不把观点长文转成全文图片。

## 7. 配图建议

第一版使用可解释的规则，标明「排版建议」，不冒充已接 AI 语义分析。以章节转折、较长文字段为候选，只建议少量位置。每条含定位、原因、建议画面、布局建议、选择图片/忽略。未处理建议不进入导出。

后续接入模型时单独配置服务，不默认发送文档给外部服务，不自动生成或插入图片。

## 8. 保存、同步与恢复

本地服务保存文章 JSON 和媒体文件。写入有版本号与原子替换，保存成功才显示「已保存」。编辑端保留应急恢复副本。网络断开显示未保存并允许重试和备份；恢复后不能无提示覆盖远端。

保存前携带 revision；远端变更时返回冲突，提供「另存副本」「加载服务器版本」。读端轮询检查变更，未编辑时载入最新；正在编辑时保护本地。两端共享同一服务才称同步。

导出可恢复 JSON 备份包含正文、样式、元信息与图片资源；HTML为阅读及迁移输出，不等于可恢复项目备份。备份导入验证结构并生成新文章，不覆盖原稿。

## 9. 发布边界

第一版不连接公众号账号、不自动发布。支持内联样式 HTML、富文本复制、封面单独下载。图片复制是否保留受微信剪贴板和上传机制影响，界面明确提醒核验；可以下载原图补传。

横滑文章导出公众号兼容版本前，明确告知转为纵排，原稿保持横滑。保留互动的 HTML 仅用于浏览器预览，不宣称微信兼容。特殊 SVG、直接同步需要真实账号和渠道验证，不能用假按钮演示成功。

## 10. 验收标准

- 320/375/414/768/1440px有明确布局规则；手机可导入、编辑、排图、预览、导出。
- 新建后实际空库无虚构内容；可主动载入示例。
- Markdown/Word导入保留文字顺序、层级、图片；危险脚本不进入渲染。
- 插入三张图片，切换双列、横滑、纵排后顺序和图注不丢；可按按钮换序和删除。
- 修改字号、行高和留白即时反映在编辑及预览；新稿能使用已保存默认风格。
- 刷新页面文章仍在；两个客户端旧版本提交得到冲突而不是覆盖。
- 断连、超限、损坏输入、复制失败有真实反馈，不出现假成功。
- 导出没有编辑控件和建议，标题不重复；兼容导出明确降级横滑。
- 构建与核心逻辑测试通过，记录尚未完成的微信真机与手机视觉验收。

## 11. 一键排版优先（2026-11-01更新）

默认流程为导入 → 自动排版 → 阅读效果 → 满意导出，用户不满意时再微调。使用已保存的个人默认风格，没有个人默认则用「留白 · 长文」。现有文章可一键重新应用，操作进入撤销历史。连续无整组图注的图片自动成组，两图并排，更多图片纵向显示；保留每张图片说明，不强制裁切。不会自动添加强调、改正文、猜标题或自动插图。手动参数默认收起，可随时展开。

## 12. 版本范围

本次交付包含完整需求、响应式可运行本地版、使用说明与验证记录。部署公网、微信授权同步、SVG轮播、AI生成图文属于后续能力。局域网同步是首版跨设备方案，公网不可达不伪称云端可用。

## 给实现方

- 这是作者本人反复使用的内容工具，主体是文章编辑画布，不做营销落地页或空数据看板。
- home描述文章库首屏顺序；channels在编辑器中可作为上下文面板，不强行变成五个独立后台。
- entities是实际保存的数据，system字段自动记录；统计均从真实文章算出，示例数字仅解释需求。
- pages中L1为列表或入口，L2为详情/编辑器；不为对称编造L3。
- primary只标记文章，图片、风格、通读和导出围绕当前文章服务。
- 必须用同一渲染逻辑驱动编辑和预览。导出使用独立、可测试的内联样式转换，并说明平台限制。
- 手机与电脑同等必需；不能用一张手机壳截图替代手机编辑。
- surface保留desktop给finesse-ui读取，同时responsive_surfaces明确包含手机；手机不是phone-only H5。
- depends_on里的未接通服务不展示成功状态，按until_then处理。
- 用户明确授权完成需求后继续finesse-ui实现，不再发起需求确认轮次。


## 13. 排版层级修订

自动识别中文编号章节、数字子节、法则编号及短独立加粗标题。明确的#主标题及副标题标签进入相应字段，不凭空撰写标题。开篇短段可标为导语；正文内容与顺序不变。编辑和导出共用blockTypography规则，大标题与副标题可单独微调字号。公众号正文不重复发布标题，副标题可作为正文开头输出。
